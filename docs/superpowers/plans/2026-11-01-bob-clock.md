# Bob Clock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed, notarized macOS menu bar app that starts and stops the workday in Bob attendance, with optional reminders, installed via `brew install --cask rikuvan/formulae/bob-clock`.

**Architecture:** A SwiftPM package with a pure, UI-free `BobClockCore` library holding all of the logic: the Bob client, state derivation, action safety, and reminder policy. A thin `BobClock` SwiftUI executable handles the menu bar, Settings, Keychain, notifications and lifecycle. A script bundles, signs and notarizes the `.app`. GitHub Actions releases it and sends a dispatch to the Homebrew tap.

**Tech Stack:** Swift 6 (toolchain 6.4, Command Line Tools only, no Xcode), SwiftUI `MenuBarExtra`, Observation, UserNotifications, ServiceManagement, Security, and Swift Testing. XCTest is **not** available with the Command Line Tools and must not be used.

**Spec:** `docs/superpowers/specs/2026-11-01-bob-clock-design.md`. Executors read the spec first. "Contract 1/2/3" below refer to its sections.

## Global Constraints

- Minimum macOS 14, Apple silicon only. `swift-tools-version: 6.0`, `platforms: [.macOS(.v14)]`.
- Bundle IDs: release `dev.richardvancamp.bobClock`, dev `dev.richardvancamp.bobClock.dev`. Product name `Bob Clock`, slug `bob-clock`, executable `BobClock`.
- Base URL `https://api.hibob.com/v1`. Auth is HTTP Basic `serviceUserId:token`.
- Start and Stop always use the current time. No retries of writes. Never close or edit entries from earlier days.
- Search fields, exactly: `/attendanceEntry/id`, `/attendanceEntry/type`, `/attendanceEntry/clockInDate`, `/attendanceEntry/clockInTime`, `/attendanceEntry/clockOutDate`, `/attendanceEntry/clockOutTime`, `/attendanceEntry/duration`. `limit: 100`.
- Coverage: two windows of 31 days each (62 days total). Each must be complete, or the result is Unknown.
- Reminder defaults: both **off**; start at 09:30, stop at 18:00, Mon–Fri. Re-evaluate after a failed check every **15 minutes**.
- Credentials live only in the Keychain: a generic password in the file-based login keychain. No `kSecUseDataProtectionKeychain`.
- No third-party dependencies.
- Tests: Swift Testing (`import Testing`, `@Test`, `#expect`). Run with `swift test`.
- The user-facing strings in the spec's tables are the source of truth for wording.

## Review Focus

These are the cases the spec implies but no state table covers. Each has a test in the task that owns the code:

1. **Pasted credentials with surrounding whitespace or a trailing newline.** These should be trimmed, and an employee ID containing anything other than digits should be rejected before any network call. (Task 10)
2. **A Bob error body that isn't JSON** (an HTML 502 page or an empty 500). The user should see a status-based message, not a decode crash or a blank one. (Task 2)
3. **A Mac that sleeps through midnight and wakes the next day.** Yesterday's ledger entry must not suppress today's reminders, and yesterday's stop reminder must not fire today. (Task 8)
4. **A notification clicked after the credentials changed to a different employee ID.** There must be no write. (Task 7)
5. **A paginating search that returns the same cursor again.** This must become Unknown, not an endless loop. (Task 6)

public protocol HTTPTransport: Sendable { func send(_ request: URLRequest) async throws -> (Data, HTTPURLResponse) }
public struct URLSessionTransport: HTTPTransport { public init(session: URLSession = .shared) }
public struct DayRange: Sendable, Equatable { public let from: String; public let to: String }   // "yyyy-MM-dd", inclusive
public enum BobError: Error, Sendable, Equatable {
  case unauthorized, forbidden(String?), notFound(String?)

  case outcomeUnknown      // request may have reached Bob (timeout, connection lost, unreadable response)

public struct ActionIntent: Sendable, Equatable, Codable {
  public let kind: ActionKind; public let employeeId: String; public let attendanceDate: String; public let entryId: Int64?
}
public enum Phase: Sendable, Equatable { case checking, ready, busy, uncertain }
public enum ActionOutcome: Sendable, Equatable { case recorded, stale, rejectedBusy, failed(BobError), uncertain }
@MainActor @Observable public final class AttendanceModel {
  public init(service: (any AttendanceService)?, now: @escaping @Sendable () -> Date = Date.init)
  public private(set) var state: AttendanceState?      // nil until first completed refresh
  public private(set) var phase: Phase                 // .checking initially
  public private(set) var message: String?             // last action message (stale/rejected/uncertain)

  public func perform(_ intent: ActionIntent) async -> ActionOutcome

- [ ] **Step 2:** Run `swift test --filter AttendanceModelTests` → FAIL.
- [ ] **Step 3:** Implement it. Two guards apply.
  - **Account generation.** `setService` increments an account generation. Every refresh and every `perform` captures the generation and the service instance when it starts, and uses only that captured service. After each `await`, if the generation has changed, the operation stops: it applies no state, phase or message, makes no further calls, and `perform` returns `.stale` (or the write's own outcome, if the write had already been sent).
  - **Sequence numbers.** Within one generation, each refresh gets a monotonically increasing sequence number when it starts. A result is applied only if its sequence number is greater than the last applied one **and** it started after the last completed mutation.
  
  Phase transitions follow Contract 2. `.outcomeUnknown` is the only error that leads to `.uncertain`.
